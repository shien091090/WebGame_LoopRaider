## 提案(LoopRaider 視覺方案 title, 美術建置設計判斷, 非老闆回饋)

放進分類: 交付自查; 建議合併到「開場 + 循環的演出接縫」那條當「同類」(不掛理念: 屬交付流程; 玩家看到的後果是 P8 的動態被一下跳格打斷)

- 同類(方案頁 / 全畫面循環沿用遊戲內函式): 方案頁要求「動態完全由 t 決定、首尾接得上」, 沿用遊戲內函式時有兩種會破功(LoopRaider 視覺方案 title 建置設計判斷, 非老闆回饋, 預防性): (1) 函式內部讀牆鐘的待機動態(終點旗飄動、寶箱閃光、巢口呼吸光、蜂彈旋轉), 同一個 t 每次畫出不同幀; (2) 函式吃 state.t 但內部是 `sin(係數 × t)`(跑步腿、拍翅、走路), 係數不是循環長的整數倍時, 直接傳秒數會在接回第 0 幀時跳一格 → 沿用前先搜函式有沒有讀牆鐘, 有就不用那個函式、在方案檔照同一造型複製一份改由 t 驅動(該作: 終點旗); 吃 t 的函式改傳 `相位 × 2π × n ÷ 係數`(n = 一圈要跑幾次的整數), 待機動態就剛好整數圈。自測除了 t = 0 與 t = 循環長逐條相同, 再比「循環長前一點點 vs t = 0」與「任意相鄰兩幀」的指令差異量, 兩者同一量級才算接得上。另: 假 ctx 用 Proxy 記屬性時要給真 Canvas 的預設值(`globalAlpha` 1、`lineWidth` 1), 否則遊戲內 `ctx.globalAlpha *= a` 的寫法會被報成 NaN, 一次幾百筆誤報
- 同一條再現(LoopRaider 視覺方案 combat-fx 建置設計判斷, 非老闆回饋, 只當證據): 玩家的無敵閃爍(`invuln`)用牆鐘 12Hz, 方案頁要演潛行「無敵、可穿怪」時不能傳 `invuln: true`, 三個方案都改成方案檔自己畫半透明 + 輪廓殼; 假 ctx 少了 `globalAlpha` 預設值, 同樣被擊倒煙與 +N 浮字的 `globalAlpha *=` 報出幾百筆 NaN 誤報。建議這條的解法再加一句: 遊戲內帶「狀態閃爍」語意的動態(無敵、受擊)也改吃 state 時間, 否則回放與方案頁都重演不了那個狀態
- 同一條再現(LoopRaider 視覺方案 repair-fog 建置設計判斷, 非老闆回饋, 只當證據): 迷霧散開要露出寶箱、巢口、終點旗, 這三個遊戲內函式都讀牆鐘(寶箱閃光、巢口呼吸光、旗飄), 三個方案檔都只好各複製一份改吃 t; 同一份造型被複製三次, 正好也是 ui 那條「字典級畫法沒匯出」的後果。建議解法再加一句: 底版裡有牆鐘待機動態的世界物件函式, 打磨時一律改成「state 有 t 就用 t, 沒有才退回牆鐘」, 方案頁、回放、說明頁就都能直接呼叫, 不必再複製
