# 美術經驗提案(收件匣)

## 提案 1 — 放進「說明頁」分類, 合併到經驗「說明頁示意圖要整塊縮放遊戲內的帶字元件」那條的尾端(第二層縮放的另一個來源: 遊戲內縮圖)

- 遊戲內有「整關重演縮圖」, 介面規定 RD 以 `ctx.scale(0.3)` 重用關卡內所有繪圖函式畫進卡片(LoopRaider explore-2 game-b 建置設計判斷, 非老闆回饋, 不算升格證據): 關卡內 18px 的「+N」浮字到縮圖只剩約 5px, 規格卻要求縮圖每次產出都冒「+N」; 說明頁再把整張卡片縮一次, 字更小 → 縮圖重用的是無狀態繪圖函式, 函式不知道自己被縮小; 「框夠大」與「第二層縮放時帶字元件以原尺寸呼叫」兩條都管不到, 因為縮放是 RD 在呼叫端做的、不是美術 → 帶字的遊戲內特效(浮字、標籤)在函式開頭讀 `ctx.getTransform()` 的縮放, 小於門檻(該作 0.5)時整組反向放大到畫面上約 13px(該作 `min(3, 0.75 / 縮放)`), 位移量不放大; style.md 判讀約定寫明門檻與倍率, 並提醒 RD 高 DPI 請用 CSS 放大、不要用 ctx 縮放(否則門檻會誤判); 自測在假 ctx 實作 `getTransform`, 以縮圖的縮放呼叫一次並印出畫布字級(待老闆試玩確認)〔P0〕〔P9〕

## 提案 2 — 併入提案 1(縮圖重用函式時浮字太小)當再現證據, 並補一個做法差異

- LoopRaider explore-2 game-a 建置設計判斷再現(非老闆回饋, 不算升格證據; 同一份介面平行兩款都踩到): 同樣是 RD 以 `scale(0.3)` 重用 `drawPopup` 畫縮圖, 19px 浮字變 5.7px。做法差異: 不叫 RD 改用 CSS 放大高 DPI, 而是把縮放除以底圖倍率(`ctx.canvas.width / 邏輯畫布寬`)換成「相對邏輯畫布的縮放」再比門檻(該作 < 0.6 時放大 `min(2.2, 0.66 / 縮放)`, 畫面約 12.5px); 這樣 RD 用 `ctx.scale(devicePixelRatio)` 做高 DPI 也不會誤判。自測用假 ctx 分別餵 (縮放 1, 寬 1280)、(0.3, 1280)、(0.6, 2560)、(2, 2560) 四組, 前後兩組字級不變、中間兩組放大。建議提案 1 的解法改寫成這個扣除法, 少一條要 RD 配合的約束〔P0〕〔P9〕

## 提案 3 — 放進「說明頁」分類, 併到經驗「guide 的『圖要示意』把整頁畫面當成一張圖描述」那條尾端的 LoopRaider explore-1 game-c 再現之後

- LoopRaider explore-2 game-a 再現(建置設計判斷, 非老闆回饋, 不算升格證據): guide 第 2 頁又寫「角落小字標 `Esc` 暫停」, 照既有解法不畫、style.md 寫明、回報點名請 RD 寫進頁面文字。同一句在兩輪 guide 都出現, 表示寫 guide 的一方還沒吸收這條分工 → 建議製作人把「沒有物件可貼的按鍵(暫停、靜音)歸頁面文字」寫進 guide 撰寫規則, 而不是每輪由美術偏離

## 提案(LoopRaider explore-2 game-c)A — 放進「說明頁」分類, 併到經驗「說明頁示意圖要整塊縮放遊戲內的帶字元件」尾端(LoopRaider explore-1 game-b 那段之後)

- LoopRaider explore-2 game-c 建置設計判斷(非老闆回饋, 不算升格證據; 物件版): guide 要畫「大地圖卡片縮圖裡重演著剛才那趟: 鑽頭號鑽擊滾石蟲、滾石蟲被擊飛撞牆化成煙」。照遊戲實際做法(卡片 × 縮圖 0.3 倍)畫, 32×44 的角色在示意圖裡只剩約 8px, 擊飛、撞牆完全看不出 → 既有經驗只處理「第二層縮放把字縮小」, 沒處理「第二層縮放把要教的動作本身縮到看不見」; guide 要教的是動作, 縮圖的實際比例只是遊戲內的限制 → 示意圖裡的「縮圖」改畫該趟的**局部放大**(只取動作發生的那一段地形, 物件約實際 0.65 倍), 外框仍用遊戲內的卡片函式, 讓玩家認得出「這是卡片上那個縮圖」; 帶字回饋(+N)照舊在外層原尺寸畫。style.md 說明頁表寫明「縮圖為局部放大, 非實際比例」(待製作人驗收)〔P0〕〔P3〕

## 提案(LoopRaider explore-2 game-c)B — 併到收件匣既有「提案 1 / 2」(縮圖重用函式時浮字太小)當再現證據
