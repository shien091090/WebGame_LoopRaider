# RD 經驗提案(待製作人審)

- 【放進「載入 / 檔案」】用腳本對 CRLF 檔做多行字串替換, 一直報「找不到 / 不唯一」(LoopRaider polish 第 4 輪) → 檔案是 `\r\n`, 腳本裡寫的多行 `old` 用 `\n` 永遠對不上(單行替換不受影響, 容易誤判成字串寫錯) → 腳本先 `split('\r\n').join('\n')` 讀入、替換完再 `split('\n').join('\r\n')` 寫回; 動手前先 Grep `\r$` 確認換行格式, 替換函式要檢查「恰好出現 1 次」否則丟例外, 失敗時不寫檔
- 【放進「計時 / 遊戲循環」或怪物 AI 類, 合併到「怪物被擊倒後仍行動」那條旁】規格要求「某狀態下所有怪物都發現不到玩家」(潛行 / 隱形)時, 漏改的多半是「平常順手讀玩家位置」的細處(轉向、面向、群體中心、預備後仍每幀追玩家的瞄準點 / 噴射方向 / Boss 肢體) → 只改「觸發條件」會留下已起手招式繼續跟著玩家轉 → 先寫一個 `hid()` 判斷, 逐種怪列出「觸發條件」與「起手後仍讀玩家位置的欄位」兩類, 後者在起手時存成怪身上的目標欄位、只在未潛行時更新; 測試用 vm 讓每隻怪(含修好工程後才出現的巢穴怪)貼著潛行玩家 240 幀斷言無攻擊狀態, 另跑不潛行對照組確認測試有效(注意把「跳蛙一直在跳」這類本來就會動的狀態排除在攻擊狀態之外)
- 【放進「Canvas / 渲染」旁的物理 / 碰撞類】飛行怪(盤旋 / 俯衝 / 回升)穿牆(LoopRaider) → 只檢查中心點或只在其中一段移動檢查, 俯衝與回升各段沒用判定框掃描; 預告線與實際停下處也分開算 → 全部移動都用「判定框下一步會不會碰實心格」檢查, 預告軌跡與實際俯衝共用同一支沿線掃描函式(每步 ≤ 2px), 回升被擋時依序試上 / 往出生點水平 / 另一側 / 原地結束, 避免卡死; 擺動基準 y 另存(不要寫死出生高度, 否則就地結束回升後會瞬移)
