# RD 經驗提案(polish 第 5 輪)

每條開頭註明要放進的分類或要併入的既有條目, 由製作人審過再併進經驗文件。

- [放進「自測」; 可併入「情境測試把角色瞬移到觸發點…」那條] 傳送型情境測試(把玩家依序傳到素材、旗子上)斷言全部誤報, 玩家其實中途被怪打死 → 傳送期間怪物照常攻擊; 有「死亡直接重生」的教學關死亡後 `R` 已是新物件, 舊斷言與保存的參照全失效 → 傳送型測試開頭把玩家無敵時間設極大(`R.p.inv = 1e9`), 每步斷言前先確認 `R.state` 仍是預期值
- [放進「自測」] 同一批測試腳本裡斷言輔助函式簽名不一致(有的 `ok(條件, 訊息)`、有的 `ok(訊息, 條件)`), 複製段落後斷言恆為 PASS 卻沒人發現 → 字串是真值, 條件位置放了訊息 → 新寫或複製腳本後先故意讓一條斷言失敗確認會報 FAIL, 同一批腳本共用同一個 `ok` 定義
- [放進「自測」; 可併入「某種敵人從不動作」旁的潛行 / 隱形測試] 「潛行中怪物不起手」情境測試先生怪、再按潛行, 怪在按下前的 3 幀已進預備, 誤報失敗 → 近距離索敵怪會在潛行生效前先起手(規格也允許「已預備的招照打完」) → 先讓玩家進入潛行 / 隱形狀態, 再生出怪並計時
- [放進「規格 / 數值驗算」類(沒有就併入「其他」)] 規格要「排除迷霧內的怪與素材」, 驗算時以為場上有它們, 實際上未修工程前它們根本不會被建立(只有修好後才生成) → 排除條件寫成「位置在迷霧外」仍正確, 但測試斷言「場上還剩 N 隻怪」會算錯 → 寫完先用 vm 列出進關後實際存在的物件與所屬區域, 再決定斷言的數字
