底版: deepen-3/game-a

## title — 開始畫面
類型: 動態
內容: 進遊戲第一個畫面。以主視覺呈現的大而顯眼小動畫, 不演玩法: 要傳達「一張由小關卡串成的冒險地圖, 打過的關會一直自己重演、源源不絕產出素材」的感覺(中央主體是一棟倉庫建築物, 不放角色; 素材在畫面裡流動進倉庫等, 不放遊戲名稱或任何標題文字)。動畫為循環播放, 一圈約 3~5 秒。底下一行「按任意按鍵開始遊戲」。
為什麼是核心: 玩家第一眼看到的畫面, 決定整款遊戲的第一印象與氣氛

## hero — 主角(三職業)
類型: 靜態
內容: 玩家操作的三個職業, 關卡內是主角, 大地圖縮圖裡回放時也一直看得到。劍士(近戰揮砍 + 衝刺斬, 開局唯一可用)、獵人(只會自動射箭, 技能是潛行)、炸彈工(拋炸彈 + 震波把怪擊飛)。三人**判定框一律 1 格高(約 28×40, 同高同寬)**, 只靠外型、配色、手持武器分辨, 不能用體型高矮區分。要表達三人個性與戰鬥方式完全不同, 且在大地圖縮小到約 1/8 時仍認得出是哪個職業。
為什麼是核心: 玩家整場都在看、都在操作的角色; 選職業 = 選路線與產出, 職業要一眼記得住才有「派誰去跑這關」的策略感

## ui — 介面風格(HUD、面板、按鈕、字)
類型: 靜態
內容: 頂端資訊列(四種素材持有數與每分鐘產量, 不標用途文字; 關卡內加上血量、計時; 不顯示這趟所得區塊)、大地圖的關卡卡片(封鎖 / 可解鎖 / 已開放 / 已過關, 已過關卡片內嵌回放縮圖與產量)、關卡面板(選職業、修工程、道具格、加速器)、背包面板(點道具格時另外打開)、升級所頁面、結算面板(新舊兩趟並排比較)、暫停 / 失敗面板、終點旗旁的「按 ↓ 完成關卡」提示、按鍵鍵帽、聲音開關圖示(右上角, 跟 `M` 鍵同步)。全部只用鍵盤操作, 選中狀態要很清楚。要表達的是一套統一的介面語言: 數字多但好讀、選中與「錢不夠」一眼看得出。
為什麼是核心: 這款一半時間在大地圖與面板裡做規劃決定, 介面就是玩法本身的一半

## materials — 四種素材
類型: 靜態
內容: 木材(開路、解鎖關卡與招募)、石頭(修工程)、水晶(在商店買道具)、魔核(只有怪物會掉, 強化角色)。同一組圖示出現在關卡地上可撿的素材、打怪掉出的素材、大地圖飛行素材、資訊列、卡片產量、面板花費、結算, 全遊戲一個長相。要表達「每種素材各有專屬用途」, 四種之間形狀與顏色都分得開, 縮小到 18px 仍認得出。
為什麼是核心: 整個遊戲的循環就是在賺這四種東西、規劃缺哪種; 玩家視線最常停留的圖示

## monsters — 怪物設計(依主題分組)與血條
類型: 靜態
內容: 每個主題有自己的怪物陣容(主題見 themes), 共 10 種一般怪 + 每主題一種巢母(Boss), 全部有血量、會主動移動, **頭上常駐血條**。要表達每種怪行為不同、要換不同打法; 預備動作(蓄力、瞄準、俯衝前的盤旋、自爆前的閃爍)要讓玩家看得到再反應; 同主題的怪配色與畫風呼應該主題。
- 翠林谷地: **野豬**(巡邏, 發現玩家後蓄力衝撞)、**跳蛙**(不停跳向玩家)、**射手蜂**(巡飛, 停下瞄準後射彈)、**刺藤花**(扎根不動, 玩家靠近時伸藤鞭橫掃前方)
- 風蝕高崖: **岩角羊**(低頭頂撞, 把玩家撞退一大段、可能撞下平台)、**俯衝鷹**(在高處盤旋, 鎖定後斜線俯衝再飛回)、**落石蜥**(趴在牆面或天花板, 朝下方丟石塊)
- 地底礦坑: **盾兵**(正面舉盾擋攻擊, 盾可被打壞, 打壞後露出本體; 有盾 / 盾已破兩種外觀要明顯不同)、**爆炸甲蟲**(爬向玩家, 貼近後閃爍再自爆; 可被擊飛去炸別的怪)、**蝙蝠群**(3 隻一群繞圈飛, 一隻一隻打)
- 巢穴怪(部分關卡的巢穴內)需與一般怪分得出; 三種巢母各對應一個主題, 體型大、血條長
為什麼是核心: 打怪是「多賺 vs 跑快」取捨的一半, 怪物是關卡裡最主要的互動對象; 主題換怪讓每個主題的戰鬥手感不同

## combat-fx — 攻擊、技能與打怪掉落
類型: 動態
內容: 關卡內每一下戰鬥的手感。包含三職業的攻擊與技能特效: 劍士揮砍(每下約 0.15 秒)與衝刺斬(約 0.2 秒的突進)、獵人自動射箭(每 0.6 秒一發)與潛行(進入、持續中、解除; 持續期間要明顯看得出無敵可穿怪)、炸彈工的炸彈爆炸(約 0.4 秒)與震波擊飛(約 0.4 秒, 怪被撞成一串時冒「N 連鎖」)。以及命中回饋: 怪物每被打掉 1 HP 就噴出 1 份素材(一擊打掉 N HP 就噴 N 份), 血條同步減少, 盾被打壞的瞬間、怪物倒下的擊倒煙(約 0.5 秒)。要表達「每打一下都有收穫」, 攻擊力越高、噴越多的爽快感。
為什麼是核心: 「怪物每損失 1 HP 掉 1 份素材」是本輪使用者明確要的打怪划算感, 戰鬥與掉落要合成同一個爽快瞬間

## replay-map — 大地圖回放與素材飛行
類型: 動態
內容: 大地圖上每張已過關的關卡卡片, 縮圖裡不斷循環重演玩家那一趟(角色、怪物、擊倒都還原)。每當回放播到拿素材的瞬間(撿到、打怪掉落、通關獎勵), 就從縮圖裡該位置飛出一顆素材, 沿弧線約 0.7 秒飛進頂端資訊列, 飛到時持有數跳一下。過關越多、同時飛的素材越多。另有加速器等級、「新區域」標記等卡片角落標示。要表達「打一次、一直賺」與「越賺越快」, 畫面越後期越熱鬧但不雜亂。
為什麼是核心: 本作最獨特的機制(平台動作 × 放置), 使用者已確認「一堆素材飛行特效的感覺很不錯」, 是玩家停留最久的畫面

## repair-fog — 工程修復與迷霧散開
類型: 動態
內容: 每關有 3 處互不干涉、可自由順序修的工程(斷橋、崩梯、堵塞隧道、巢穴門)。未修時是斷掉 / 塞住的結構, 後方要開出的區域蓋著戰爭迷霧(迷霧下的區域有實體阻擋、進不去), 旁邊立工程牌標出這處是捷徑、寶區還是巢穴。在關卡面板花石料修好的瞬間: 結構變成完整的橋 / 階梯 / 打通的隧道 / 打開的巢穴門, 同時該區迷霧約 0.8 秒散開, 露出裡面的素材、寶箱、怪物。關卡畫面、面板預覽、大地圖縮圖都看得到修復狀態與迷霧。要表達「關卡變大了、有新東西可拿」的開拓感, 以及未修 / 已修一眼分得出。
為什麼是核心: 熟關後重新挑戰的主要動機(修好想回去重跑), 是石料唯一的用途, 也是關卡長相隨進度改變的地方

## themes — 關卡主題
類型: 靜態
內容: 8 關分成 3 個主題, 每個主題 2~3 關, 主題決定背景、地形磚、平台與裝飾、配色與出現的怪物(見 monsters):
- **翠林谷地**(第 1、2、3 關): 起點的森林與谷地, 木棧道、藤蔓、樹根平台, 明亮溫暖
- **風蝕高崖**(第 4、5 關; 第 8 關是最終 Boss 關, 專屬場景見 boss-stage): 高台與寬坑的崖壁、吊橋、風蝕岩柱, 天空開闊、偏冷色
- **地底礦坑**(第 6、7 關): 礦道、礦車軌道、木支架、裂岩牆與晶礦, 暗色中有礦燈與晶光
同主題內每關的地形配置各不相同(不是同一張圖換怪), 主題之間在縮成大地圖縮圖時也要一眼分得出。工程結構(斷橋、崩梯、堵塞隧道、巢穴門)與迷霧也要配合各主題的材質。
為什麼是核心: 使用者要求打磨版關卡重新設計、分主題且各關地形有差異; 主題是關卡畫面的主體, 也是大地圖上分辨各關的依據

## stage-panel — 關卡準備頁
類型: 靜態
內容: 從大地圖選某關進去後的準備頁: 關卡預覽(含修復狀態與迷霧)、選職業、修工程(3 處, 花石頭)、道具格(點了另開背包)、加速器、最佳紀錄 / 產量、開始挑戰。三個方案要是**版面結構完全不同**的設計(例: 左預覽右選單 / 預覽全螢幕疊面板 / 分頁步驟式), 不只是換配色。介面風格沿用已選的 ui 方案 A(options/ui-A.js)、素材圖示沿用 materials 方案 C(options/materials-C.js)。全部只用鍵盤操作, 選中狀態要清楚。
為什麼是核心: 每次出關前都在這裡做規劃決定(派誰、修哪、帶什麼), 使用者對現行版面不滿意

## skill-cd — 技能冷卻顯示
類型: 動態
內容: 關卡進行中技能冷卻與「可用」提示。現行放在頂端資訊列太不明顯、看不出冷卻好了沒。三個方案要放在**不同位置 / 不同表現**(例: 角色頭頂或腳下的環形計量、畫面下方大圖示加倒數、角色身上發光 + 冷卻完成時的閃光提示), 動畫要演出「施放 → 冷卻中倒數 → 冷卻完成」一整圈。三職業技能: 劍士衝刺斬、獵人潛行(冷卻較長)、炸彈工震波。介面風格沿用 ui 方案 A、角色沿用 hero 方案 A(options/hero-A.js)。
為什麼是核心: 技能是路線與打法的關鍵, 冷卻好沒好一眼要看得出來

## final-boss — 最終 Boss(外觀與行為模式)
類型: 動態
內容: 最後一關(第 8 關, 場景見 boss-stage)的最終 Boss, 其他 7 關全部通關才解鎖該關; 打倒後進入結局。體型遠大於巢母, 頭上長血條, 分 2~3 個階段(血量降到門檻換招式與外觀變化)。三個方案要是**外觀與行為模式都不同**的 Boss(例: 巨型生物 / 古代機關造物 / 吞噬素材的魔物), 動畫演出一輪招式循環: 每招都有看得見的預備動作, 並留出玩家可反擊的空檔; 被打時同樣每掉 1 HP 噴 1 份素材。三職業(劍士近戰、獵人自動射箭 + 潛行、炸彈工炸彈 + 震波)都要打得過。角色沿用 hero 方案 A、怪物畫風沿用 monsters 方案 B。
為什麼是核心: 使用者把遊戲終點改成「打通其他關 → 挑戰最終 Boss → 結局」, Boss 是整趟冒險的收尾高潮

## ending — 通關動畫
類型: 動態
內容: 打倒最終 Boss 後播放的結局動畫(約 8~15 秒, 播完可按任意鍵回大地圖繼續玩)。三個方案要是**不同的演出概念**(例: 大地圖 8 關一齊亮起、素材湧入倉庫 / 三職業在高崖上看日出 / Boss 崩解後世界恢復原貌), 最後收在一個可停留的畫面(顯示通關時間等)。開始畫面已選 title 方案 B(中央一棟倉庫), 可呼應; 角色沿用 hero 方案 A、介面沿用 ui 方案 A。不放遊戲名稱。
為什麼是核心: 給整趟冒險一個完整的收尾, 打完 Boss 的成就感靠這段放大

## boss-stage — 最終 Boss 關場景
類型: 靜態
內容: 最後一關(最終 Boss 關)的專屬場景, **全新主題, 不沿用翠林谷地 / 風蝕高崖 / 地底礦坑**。Boss 是 final-boss 方案 B「守門巨像」(懸在正上方、左右對稱的砂岩古代機關, 用分離巨拳、大眼光束、碎岩塊攻擊, 三階段肩甲噴飛、臉裂紅縫、頭殼裂開露出核心眼), 場景要與它的氣質相配、也要給它的招式留出空間(巨拳落點、光束掃射範圍、碎岩落下處)。內容包括背景、地形磚、平台與裝飾、配色, 平台配置要讓三職業(劍士近戰、獵人自動射箭 + 潛行、炸彈工炸彈 + 震波)都有閃避與反擊的位置。三個方案要是**概念完全不同**的場景(地點、氛圍、色調都不同), 每個方案把 Boss 放進場景裡一起畫出來看整體效果。大地圖縮圖時也要一眼看得出這是最終關。角色沿用 hero 方案 A。
為什麼是核心: 使用者要最終 Boss 關有專屬於它的場景, 是整趟冒險最後的舞台

## death-anim — 死亡動畫
類型: 動態
內容: 角色血量歸零時播放的死亡動畫(約 1~1.5 秒), 播完才跳出重來彈窗, 不是瞬間跳窗。三職業共用一套演出或各有變化皆可。三個方案演出概念要不同。角色沿用 hero 方案 A(遊戲現行 polish/game/game/art/art.js 的畫法)。
為什麼是核心: 使用者回饋死掉瞬間跳窗太突兀

## clear-anim — 過關動畫
類型: 動態
內容: 在終點旗按 ↓ 完成關卡後播放的短暫過關動畫(約 1~1.5 秒), 播完才出結算面板。三個方案演出概念要不同(例: 旗子升起 + 角色歡呼 / 素材匯聚爆開 / 鏡頭收光圈)。角色、旗子沿用遊戲現行畫法。
為什麼是核心: 使用者要過關有一個收束瞬間

## result-panel — 結算面板
類型: 靜態
內容: 過關後的結算面板: 「這一趟」與「目前回放」兩欄並排比較(通關時間、各素材數、每分鐘產量), 選留新或舊回放。「這一趟」欄位要明顯凸顯、一眼和「目前回放」分得開(三個方案用不同手法: 例如亮底大字 / 外框發光加標籤 / 卡片浮起)。介面沿用 ui 方案 A 與遊戲現行畫法, 素材圖示用遊戲現行的(石頭、水晶、魔核、木材)。
為什麼是核心: 使用者回饋「這一趟」不夠顯眼

## unlock-fx — 解鎖職業特效
類型: 動態
內容: 升級所裡花素材「解鎖職業」(原「招募」, 已解鎖狀態顯示「已解鎖」)那一刻的特效, 約 1~1.5 秒, 職業卡從鎖住變成可用。三個方案演出要不同。角色沿用 hero 方案 A、介面沿用遊戲現行畫法。
為什麼是核心: 使用者要解鎖職業有慶祝感

## map-card — 大地圖關卡卡片(修復外觀與裝置格)
類型: 靜態
內容: 大地圖上的關卡卡片, 不再顯示「工程 N/3」文字, 改用外觀表達修復進度: 一處都沒修時卡片 / 縮圖有殘破、缺漏的不完全感, 每修一處就更完整, 3 處都修好是完整的樣子(方案圖要並排畫出 0/1/2/3 四種狀態)。卡片上另有兩格裝置格: 沒裝裝置是空格, 有裝顯示該裝置的小圖示。三個方案表達殘破的手法要不同(例: 卡片邊框缺角裂開 / 縮圖褪色蓋灰 + 修好處上色 / 卡片上的小建築逐步蓋好)。其餘卡片內容(回放縮圖、產量、已過關)照遊戲現行。
為什麼是核心: 使用者要大地圖一眼看出各關修了多少、裝了什麼

## devices — 裝置(原道具)與裝置倉庫
類型: 靜態
內容: 原「道具」全部改稱「裝置」: 是安裝在關卡上的設施, 不是給角色拿的東西。把遊戲現有的每一種道具(含已改成道具的加速器, 清單照 polish/game/spec.md)重新命名並重畫成裝置的樣子(機械、設施、裝在地上或牆上的感覺), 圖示縮小到卡片裝置格大小仍認得出。同時畫「裝置倉庫」面板(原背包): 只列還沒安裝的裝置, 已安裝的不顯示, 也不顯示第幾關第幾號。三個方案在裝置的造型語言與命名風格上要不同, 每個方案附上每種裝置的新名稱。介面沿用 ui 方案 A。
為什麼是核心: 使用者要把道具的概念改成裝在關卡上的裝置

## map-layout — 大地圖版面(升級所與商店區)
類型: 靜態
內容: 大地圖整體版面: 現在右側約 1/3 空著只有紫色背景, 改成關卡區靠右、左側空出一塊放「升級所」與「商店」(商店用水晶買裝置, 每種有數量上限, 買完就沒了; 從關卡準備頁搬來), 兩區用不同背景或分隔線清楚區隔。三個方案版面與區隔手法要不同。關卡卡片、頂端資訊列沿用遊戲現行畫法(畫布尺寸照 polish/game/interface.json)。
為什麼是核心: 使用者回饋大地圖空了一塊, 並要把商店移到大地圖跟升級所放一起

## tut-arrow — 教學大箭頭
類型: 動態
內容: 新手教學全程共用的「大箭頭」: 指向大地圖第一關卡片、關卡準備頁「開始挑戰」按鈕、關卡內的角色 / 素材 / 怪物 / 終點 / 修復點。要大而顯眼(比現行教學提示存在感強很多), 帶持續的引導動態(例: 朝目標彈跳 / 脈動發光 / 外框流光), 能朝任意方向指。三個方案造型與動態要不同, 方案圖並排畫出它指向大地圖卡片、按鈕、場景物件三種情境。介面沿用 ui 方案 A 與遊戲現行畫法。
為什麼是核心: 使用者覺得現行新手教學太沒存在感, 改成用大箭頭強力引導

## tut-text — 教學提示文字框與逐字動畫
類型: 動態
內容: 搭配大箭頭的提示文字框, 文字以小動畫逐字顯示(三個方案的逐字手法不同: 例 打字機游標 / 每字彈跳出現 / 每字淡入上浮)。字要大、在任何背景上都清楚。範例文字用「這是你」「這是素材,多多收集,不同素材有不同用途」「收集素材後可以修復通道, 解鎖更多可以去的地方」「直接按Z開始關卡吧!」(其中 Z 用 keycap 按鍵外觀嵌在句中)。另畫「按 Z 繼續」的推進提示(提示框角落的按鍵外觀 + 小動態), 以及文字在顯示完後再往後逐字接上一句的樣子(例「接著會不斷重演剛剛的通關歷程」→ 接「, 源源不絕累積素材」)。介面沿用 ui 方案 A。
為什麼是核心: 教學全程靠提示文字引導, 要有存在感且好讀

## keycap — 按鍵外觀
類型: 靜態
內容: 全遊戲按鍵提示統一用的按鍵外觀(鍵帽), 取代純文字的「Z」「X」「↑」等: 畫出 Z、X、←、→、↑、↓、Esc 的樣子, 以及嵌在一行文字中間時的樣子(例「直接按 [Z] 開始關卡吧!」「Z購買」)。要有按鍵立體感, 小尺寸仍認得出。三個方案造型不同(例: 立體鍵帽 / 扁平圓角徽章 / 像素風機械鍵)。介面沿用 ui 方案 A。
為什麼是核心: 使用者要所有按鍵提示都有按鍵的外觀, 不是純文字

## ctrl-panel — 操作方式面板
類型: 動態
內容: 教學中從角色身上淡入出現的「操作方式」面板: 標題「操作方式」, 列出 ←/→(移動)、↑(跳躍)、Z(攻擊)、X(技能)每個按鍵旁附功能小字(按鍵用 keycap 外觀)。淡入後縮小並移到畫面左上角, 之後整關都固定在左上角給玩家查看, 不擋路線也不蓋到頂端資訊列。方案圖要畫出: 在角色身上展開時、移動途中、停在左上角時三個樣子。三個方案版面與移動演出要不同。
為什麼是核心: 教學要讓玩家隨時查得到操作方式

## tut-spotlight — 修復點強調
類型: 動態
內容: 教學最後一步: 關卡內 3 個待修復點(工程牌 + 結構格 + 迷霧)同時顯示輪廓邊緣光, 其餘場景稍微壓暗, 三個大箭頭同時指向三個修復點, 配提示文字「收集素材後可以修復通道, 解鎖更多可以去的地方」。三個方案的強調手法要不同(例: 描邊流光 / 聚光燈挖洞壓暗 / 脈動光暈)。場景、工程牌、迷霧、結構格沿用遊戲現行畫法, 大箭頭與文字框可先用暫定樣式。
為什麼是核心: 讓玩家第一次就懂修復點是什麼、能解鎖新區域

## respawn — 重生落下
類型: 動態
內容: 第一關(教學關)被怪物打死時不跳失敗彈窗: 死亡動畫播完、停頓片刻, 角色從起點上空掉下來重新開始。畫出角色從畫面上方落到起點的過程與落地瞬間的表現。三個方案演出要不同(例: 光柱降下 + 落地光圈 / 從雲中掉下落地彈一下壓扁回彈 / 傳送光點聚合成形再落地)。角色沿用 hero 方案 A 與遊戲現行畫法。
為什麼是核心: 教學關死掉要不打斷節奏, 直接重來

## tut-summary — 新手教學總結板
類型: 動態
內容: 教學最後在畫面中央出現的大板子, 標題「新手教學總結」, 下面 4 個圖文區塊依序以小動畫出現, 每塊配一張對應的遊戲畫面小圖(用遊戲現行畫法縮小呈現): 1「刷關卡」(角色跑關卡) 2「刷越快,素材累積越快」(回放 + 素材飛行) 3「素材可解鎖修復工程、解鎖新關卡」(修復點 / 新關卡卡片) 4「有空也多去升級所和商店看看吧!」(升級所與商店圖示)。最下方「按 Z 關閉」(按鍵外觀)。三個方案版面與區塊出現動畫要不同(例: 2x2 卡片依序翻出 / 橫排四格依序滑入 / 直列條目逐條展開)。介面沿用 ui 方案 A。
為什麼是核心: 教學收尾要一次總結整個遊戲循環
